# 管理中心部署与证书边界

管理中心包含 console 与 PostgreSQL。当前为源码修订，正式新镜像的构建与部署验收仍待完成；当前运行现场未替换。完整的首次部署向导、本地 agent 设置入口和界面维护重启仍是内部待办，不能把现有流程称为“全部界面化完成”。

## 证书与状态

容器只接收三个只读 bootstrap 文件：

| 宿主文件 | 用途 |
| --- | --- |
| `tls/server.pem` | 中心 HTTPS/gRPC 服务器证书 |
| `tls/server.key` | 对应服务器私钥 |
| `tls/ca.pem` | 公开的网关客户端信任锚 |

CA 私钥与网关私钥留在签发/部署端，不挂载进容器。Compose 关闭缺失文件自动建目录；演示生成器可能在宿主 `tls/` 留下 `ca.key`、网关 key，这些不是容器挂载内容。CA 托管签发若后续启用，采用单独、受审计的组织托管入口。

root 入口仅把这三个只读输入复制到 root 所有目录下的新建私有运行目录，再降权。TLS/客户端 CA 的上传、核对和启用由非 root 服务操作私有状态卷；入口不复制或覆盖用户暂存文件。

## 界面操作

浏览器访问 `https://<中心地址>:18443`。首次登录修改初始管理员密码，随后使用独立组织账号。

- 设置页可直接选择服务器证书、私钥、公开 CA 文件，核对指纹后确认上传。
- 服务端证书必须与可解析私钥配对；客户端 CA 必须处于有效期、具备 CA 标志及适当签发用途。
- TLS/CA 写入完整生成版本和待启用指针；当前实现下次服务启动启用，保留 bootstrap 和旧版本。界面维护启用按钮仍待实现；维护阶段可使用容器平台重启操作。
- 任务密钥在线轮换保存新旧恢复材料并重加密任务及未领取身份包，无需重启。备份以当前运行密钥为准；恢复先核对数据库绑定，避免错误备份覆盖当前密钥。
- 网关登记、一次性身份包及客户端证书轮换使用中心界面；独立 agent 导入/激活与能力配置目前仍有 CLI/env 步骤，后续本地设置界面将补齐。

原有单文件 TLS/CA 暂存不自动应用、删除或改写；需要显式核对。当前旧式暂存处理尚未提供完整 UI，升级验收须覆盖该路径。

## 备份与升级

保留配套 PostgreSQL 数据和完整 `console-data` 卷；后者包含任务密钥、`pending/keys/`、TLS/CA 生成版本、活动/待启用指针及其他持久状态。组织备份和恢复材料应具备可交接的权限与恢复流程，不能只依赖一人保管。

当前外部地址的 Origin、数据库连接等启动参数仍由部署配置提供；首次配置向导尚未实现。CLI 是维护后备入口，不作为最终产品界面化完成的证明。现有 UNKNOWN 保持按原编号核定、不重发。

## 开发机构建与启动

在仓库 `docker/` 中准备证书后，按部署平台加载/构建镜像并启动 Compose。维护者命令：

```sh
cd kura-management-console
docker build -f docker/Dockerfile -t yofc-management-console:latest .
cd docker
docker compose up -d
```

镜像构建上下文通过 Dockerfile 专属 ignore 白名单限定，不包含 `docker/tls/`、运行现场或 `target/`。启动与升级前保留既有卷与证据，正式环境部署另走对应验收。
