# 在界面生成服务器 CSR 和更换证书

首次设置完成安装凭据配对后，在「证书」中选择「在中心生成密钥和 CSR」。日常换证在管理员「设置 → 服务器证书」中操作。

1. 核对完整 HTTPS 中心地址，填写域名或 IP 和需要的端口，不附加路径或末尾斜杠。
2. 点击「生成服务器 CSR」，下载公开的 `.csr` 文件。服务器私钥保留在中心，页面不会下载或上传这把私钥。
3. 将 CSR 交给外部 CA，按该组织已有审批程序签发服务器证书。CA 私钥不上传中心，不放进中心容器挂载目录。多人保管及审批策略由外部 CA 执行；本功能没有替代该审批程序。
4. 上传签回的服务器证书 PEM。页面在发送前保存本次上传编号和公开证书摘要，中心保存对应的原上传记录。中心验证密钥匹配、域名/IP、有效期、服务器用途及非 CA 约束。明确验证拒绝时可以在原 CSR 上选择更正后的证书，使用新上传编号；旧拒绝回执保留。响应丢失时，刷新或点击查询只读取原上传的持久回执，不重新上传。校验拒绝回执可恢复更正入口，精确绑定的签回成功回执可恢复成功显示；缺少回执仍为 UNKNOWN。
5. 首次设置：再上传校验网关用的公共 CA 证书、填写专用数据库及组织管理员资料，核对指纹后初始化。初始安装的原请求和成功回执持续保留。
6. 日常换证：核对指纹后暂存，再在「证书与信任配置生效」中核对本批服务器证书、网关 CA 和网关影响，显式确认生效。下载 CSR、上传签回证书或暂存都不会自行切换当前 TLS。

旧证书和私钥已经存在时，可以在没有待核定 CSR 的情况下选择「导入已有服务器证书和私钥」。尚未使用且有确认回执的 CSR 可以显式停用；停用保留密钥和历史，不吊销证书，不更改当前 TLS。已用于首次安装或已暂存的记录不可作为未使用 CSR 停用。

遇到 UNKNOWN、请求失败、刷新后原编号无记录等情况，保留原编号并使用「查询原 CSR 请求」。不要重发、更换编号或删除本地记录来绕过未知结果。

上传历史与注册清单、CSR 编号、证书摘要、提交人和签回回执相互绑定。缺失原上传、历史清单或签回回执时，现有证书文件不能代替成功回执；新的上传、旧证书导入和 TLS 生效入口保持阻断。旧客户端的导入格式继续兼容，但旧的未决上传没有新上传编号时不能被当前证书状态补造为成功。服务器私钥、CA 私钥和证书原文都不写入浏览器的上传跟踪记录。
