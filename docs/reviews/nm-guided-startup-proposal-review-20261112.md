## Actual connected preparation

Local admin RPC `network.nm.ownership.startup.prepare` accepts exactly the
original operation ID and parent confirmation token. Coordinator validates the
actual original actor/fenced plan and fresh NM/backend CAS. The handover Store
then binds its new private child intent/journal to that parent plan and to the
same no-follow network marker descriptor/device/inode/content. It does not
replace the parent intent or create a second adoption prototype.

Production reads the installed grant at the fixed internal location
`/etc/kura-management-agent/nm-ownership-profile.json`. The request cannot supply
a path, unit, executable, provider/readiness flag or epoch. No operator environment
variable was added. The eventual installer/wizard must generate this grant;
manual grant-file preparation is not the final deployment workflow.

The implementation reuses the existing ordinary profile trust/token parser,
file/hash inventory and effective systemd definition checker. It also reuses the
system-control unit/cgroup identity observer through a read-only wrapper. The
ordinary-profile changes expose these existing functions inside the Rust crate;
they do not change old recovery or restart/reboot grants or their wire bytes.

Preparation reads the actual fixed unit twice, requires a running unit, and
rechecks the grant, all pinned inputs, exact argument-file identity, effective
definition and fence preimages before publishing only private review evidence.
The child has its own actor-bound token/expiry. Missing, malformed, replaced or
partially published evidence is not treated as absence. The original query reads
retained evidence without contacting a unit or reproposing anything.

The generated target preserves other arguments, literal secrets and all other
external PID reservations. It selects the existing fixed network PID, the actual
`nm-agent-v1` confirmed provider, the firewall provider and an original-operation
profile identity. The hash-only shape introduced in schema2 and retained in schema4 carries the generated ordinary grant and before/after
argument hashes, file identity and Kura home. It does not copy either argument
body into agent state. Execution must re-read the unchanged original or its
Kura-owned retained preimage, regenerate the target and compare the exact planned
hash before publication. Public/status projections contain only identities,
hashes and the controlled changes, never raw arguments/grants or a token.
Only the original actor can retrieve the child token. Existing fences are bound
for retention; absent firewall/framework fences are proposed create-only. They
are not created by preparation and are not a rule-ownership proof.

Direct Java and the existing pinned packaged launcher are supported. Direct
launch requires all Java arguments to come from its one pinned argument file.
For the packaged contract, Kura home must match the installed launcher's actual
home, and explicit later overrides of controlled properties are refused. The
shared checker still pins the launcher/generator, effective environment and
argument-file binding. This is not general shell attestation or full effective
startup/foreign-writer proof.
