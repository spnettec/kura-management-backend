## Current implementation

Registered Kura alone may read `network.nm.template.confirmed` and `.chunk` through
the actual captured connection epoch/UID. These reads use the fixed retained
handover state and root observation lock, without live Core calls or dependence
on the optional NM writer engine. PREPARED/absent/cancelled templates are refused;
FENCED/LEASE_INTENT/COMMITTED require the original ready template and matching
physical marker identity. The metadata exposes only original plan/template IDs,
source/confirmed revisions and roles. Chunk reads accept no PID/path and must
match the original operation/plan/template/index. READY alone still grants no lease.

The actual Java `NmConfirmedConfiguration` external handler obtains bounded
ciphertext chunks over one pinned registered connection and decrypts only in Kura.
It validates exact schemas/counts/bindings/hash/GCM, checks the complete decrypted
role projection against agent-confirmed roles and rereads the metadata before
returning. Metadata generation receives a detached typed copy; mutation of its
arrays cannot alter the returned mirror. Full scalar/Password/array/List/Vector
values and literal `encrypted:` password content remain intact. Old or missing
bounded transports/key/metadata providers refuse; there is no CM/snapshot fallback.
Changed connection/provider/generation cannot return a stale mirror.

NM implements the new read-only `NetworkConfigurationMetadataService` through
its original complete definition builder, without CM/backend/crypto dependencies
or calls back into Core. The API package remains the unreleased additive
net.transaction1.1. Bridge's bounded connection API is1.2; the tracked importer
accepts it. Descriptor references are optional0..1. The external handler registers
only when the startup contract selects `kura.network.confirmed.provider=nm-agent-v1`
and reserves the fixed PID in `kura.configuration.external.pids`. Neither setting
is an adoption proof. A legacy PID reservation alone must not register this new
handler or conflict with a retained Netplan provider. These internal settings
must be generated by the guided profile flow, never manual operator env steps.

Identical configuration updates/full snapshots are read-verified no-ops. Changed,
incomplete or wrongly typed owned network values require a joint agent plan;
the handler never rewrites NM while handling generic Core updates/rollback.
Current mirror content is the original confirmed baseline; later role/profile
generations and typed deltas are not implemented yet.

Local `ownership.fence`/`.activate` now join the original operation/actor/token
state machine. Fence dispatch remains once-only. Activation verifies the original
backend, releases the OS guard for the actual Core owner/drained-writer read
(which calls back into the agent), reacquires it, checks the current authenticated
registration and fresh backend again, then publishes a schema2 lease with the
actual owner observation. A controlled Kura restart may establish a new epoch;
the proof must be from the real current connection, never caller JSON readiness.
Only this full-owner read has a20s budget for its reverse chunk calls; existing
ordinary read2s and write25s budgets are unchanged.

Original LEASE_INTENT adjudication verifies the actual current owner and only
the existing original lease/receipt; missing evidence stays UNKNOWN. It never
recreates a missing lease/activation receipt, republishes a marker or exports
again. A valid committed lease works with Kura unavailable. Legacy absent fields
stay absent. NM ownership controller admission may lock incomplete ownership
evidence to inspect its original record; all other writers still require fully
settled evidence and the controller itself validates each original before acting.
