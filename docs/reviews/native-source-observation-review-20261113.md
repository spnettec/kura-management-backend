## What changed

An effect-free source observation can advance the imported physical source after foreign or NetworkManager content changes in the same physical epoch. It uses the original initialization receipt, original delegation, current source stamp/revision, fresh registered Core/startup/runtime/network cohort, and a separately constructed `Observed` capability. Ordinary `Verified` update authority still requires the entire prior normalized native source and kernel generation to match. The two capability types are not deserializable and have no conversion into each other.

The protected scope retains actual kernel table/chain handles, base policies, selected owned rule handles, relative owned order, complete JSON and raw parameter semantics. Known receipt table names come only from replaying acknowledged original transfer history; their complete contents stay protected. Foreign lookalikes are not adopted by name. New foreign rules in shared base chains remain foreign to the next strict update. Missing epoch/raw/generation, changed protected declarations/handles, lost/reordered/modified owned rules, incomplete model or unchanged physical source are refused. An observation does not establish lawful restoration after a reboot, namespace replacement or recreated owned rules.

The event is `SOURCE_OBSERVATION`, transaction schema 3, with `OBSERVING` and `OBSERVED` states. Original schema 1/2 transaction bytes and pointer schema 1 remain compatible. An observed event advances the physical head without changing the logical policy revision, destination prefixes or original ownership baseline. It is distinct from no-effect cancellation/NACK, which does not advance the head. The record rejects every forward/inverse dispatch, capture, ACK/NACK and confirmation bit. There is no native sender or confirmation path.

The producer uses the same system EX guard, transaction marker, create-only history, bound plan artifact and confirmed pointer. It reserves record/artifact/native/history headroom. A first original publication may occur only while the durable intent proves it has never been attempted. Once attempted, missing final history remains UNKNOWN; neither replay nor a new operation ID reconstructs it. An existing exact final history may repair the original pointer/final marker without replacing history. A fully settled original query is read-only, works through the metadata route with writes disabled, and grants no current ownership. Orphan/unreachable history and unfinished work block new IDs.

The live entry point still checks the original installation identity under production EX admission before collecting live authority. Temporary storage fixtures cannot bypass this. Reverse Core/CM/drain calls run without holding EX; the fresh context, source stamp, original owner, association, current runtime, network cohort, full observed native digest and physical epoch are rechecked after reacquiring EX. A stored receipt is never a new live grant.
