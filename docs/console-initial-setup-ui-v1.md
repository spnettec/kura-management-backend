# 中心首次配置向导：应用内闭环（V52）

2026-11-14；同一 R013 shadow 增量，未应用至原仓库，未提交推送。方案 A：外部 CA，CA 私钥不进入中心；组织 custody 和多人审批未在本增量实现。

## 已实现的应用流程

`serve` 在无持久配置、无完整 legacy 环境配置时，先启动独立 HTTPS 设置页，不连接数据库、不生成任务数据密钥绑定、不创建默认管理员。安装过程生成当前用户私有的安装凭据与临时服务器身份，页面先由操作者核对浏览器安全详情中的指纹与可信安装器凭据一致，再上传安装凭据文件解锁。页面返回的指纹只是辅助核对，不能证明浏览器与可信安装器一致；首次信任需安装平台的可靠交付通道。

设置页输入中心地址、代理监听地址、数据库主机/端口/名称/账号/密码，选择服务器证书/对应私钥和公共客户端 CA，设置组织标识和强口令管理员，核对指纹后提交。服务器重新校验身份材料、有效期、origin 主机名和服务器用途；客户端专用证书不能作为服务器证书。只接受专用空 PostgreSQL schema，已有业务表不迁移、不改写、不创建管理账号。

私有任务密钥由中心为本次 generation 创建；已有或已提交的密钥不覆盖或重生成，执行前拒绝的草稿保留。证书、密钥、配置和材料摘要保存在不可覆盖的 installation generation。数据库初始化完成后记录安装 ID、原请求 ID 和配置摘要，持久选择该配置，再创建原回执。原监听 socket 随后交给正式 HTTPS，gRPC/mTLS 启动；无需用户手工重启，首次阶段和正式中心是同一进程。后续启动从私有配置加载，环境变量仅作高级覆盖。已配置安装须先在目标数据库验证安装绑定和有效管理员，之后才运行迁移；不会回落到 admin/admin。

## 权限和原操作

安装凭据 0600、私有目录 0700，令牌不进入响应或日志。配对校验安装 ID/令牌、HTTPS Origin 与 HTTP/1 Host 或 HTTP/2 authority，限速后发 Secure/HttpOnly/SameSite=Strict cookie。配置写入另需 CSRF，正常服务启动后安装写接口消失；只有登录的组织管理员可以从正式接口读原记录。

界面先保存原 ID 和公开目标信息，数据库密码、口令、PEM/私钥不进入 localStorage。服务端在异步验证之前先持久记录 accepted，后台真实任务独立于 HTTP 连接继续执行；只有实际仍活着的 JoinHandle 才报告 PENDING。失去任务句柄且无回执为 UNKNOWN，不根据锁文件或时间推断。原 accepted/intent 阻止新 ID 绕过，重复同 ID 只查询，改变同 ID 的内容拒绝。已知执行前失败记录 REJECTED，允许重新核对；缺回执/404/丢响应不授权重发。UNKNOWN 的显式核定/恢复仍为内部待办。

数据库会话级安装锁在结束时显式释放或关闭连接，不能把持锁连接交回池。首次配置和正常运行沿用相同 state 独占租约；同 state 的第二个进程在数据库和监听器之前被拒绝。安装的持久指针、材料私有路径和摘要受校验，损坏时不默默使用默认配置。尚无 active 配置但已存在首次配置 accepted/intent/receipt 时，共用连接入口拒绝 legacy fallback；即使设置完整旧环境变量，`migrate` 等启动准备也不能绕过原 UNKNOWN 去接触数据库或创建密钥。已配置安装仍须先验证数据库绑定。

## 本阶段实际证据

- 11 项新 Rust 回归通过：私有临时身份及不重生成、安装/Origin/CSRF、真实任务句柄与 UNKNOWN、原 ID/新 ID 阻挡、执行前拒绝、篡改/路径逃逸、客户端证书用途拒绝、响应不泄漏凭据、HTTP/2 authority、首次记录阻挡 legacy fallback，以及 128 个原生 P-256 PKCS8 密钥均可被实际 TLS provider 加载。
- 两套独立真实浏览器首次配置通过，中英各一次，均不向中心传 DATABASE_URL、数据密钥、origin 或 TLS 文件环境变量。中文原请求 0cadf1b7-8040-481a-b501-53ee9e05d996，进程1565；英文 27523ffd-f911-4d0d-8638-f701b2ce8d15，进程1794。每套均同一进程切换、选择的组织管理员登录、读取原回执、刷新不重发；数据库各一个自定义管理员、一条初始化审计、一个安装绑定，无默认 admin。两套首次动作已闭环，驱动会拒绝任何已有 accepted/intent/receipt 的场景。
- 配置持久性：中文安装后以当前代码正常启动，不提供上述 legacy 环境字段，安装/证书/私钥/数据密钥摘要和账号/安装审计计数保持；不重新初始化或生成密钥。该进程为2059。一次观测使用 Python 严格验证器时，旧 TEST ONLY 证书因缺 AKI 被拒；同一活进程继续核对，OpenSSL/curl 实际验证 CA 和主机名通过，没有改验证器标志、全局配置或因观测失败再重启。该测试证书严格互操作边界保留。
- 有真实业务表的独立 schema 被拒绝，原表/原值不变、无迁移/管理员创建；已配置安装用高级 URL 覆盖指向另一个空库时，在任何 DDL 或密钥绑定前拒绝，目标仍0表；实际第二进程共用 state 被拒绝，原进程及16文件保持。这三项与配置持久性均为新的有限范围检查。

合计18种新检查：11单元、2真实首次UI、独立已有数据库拒绝、错误目标库迁移前拒绝、配置持久性、第二进程拒绝，以及普通可执行程序对测试故障 journal 的 legacy `migrate` 拒绝。最后一项使用不可连接数据库端点，确认在连接之前返回特定原记录保护错误，journal不变、无密钥/配置产生。

最终编译制品另作只读接纳核验（PID3207）：16个状态文件和数据库账号/安装/crypto/唯一初始化审计摘要完全一致，未再次初始化或生成密钥。当前普通 macOS ARM64 non-test debug SHA f79a03e64bdbbac5c00bdea5511959cb6365a351a5d98634d506b20be188c2b9；该接纳后本批新测试服务停止、数据保留。前一仅格式化版本 aae27f4b 的 PID2481 接纳证据保留。新增启动保护后的接纳观测曾先后因测试脚本假定 postgres 用户及错误审计字段而失败，两次均在中心启动之前；修正为夹具实际用户和实际 operation 字段、要求恰一条 COMMITTED 后完成接纳，没有重放初始化。证据在 target/nm-role-authority-20261112/registered-runtime-v52/console-first-setup-ui-v1。首次测试的 OpenSSL/LibreSSL 编码/请求配置问题、SQLx测试构造错误、一次拒绝旧场景的驱动选择错误和严格验证器观测失败均保留。Bootstrap 私钥最终由原生 ring PKCS8 生成，OpenSSL 仅以私有最小配置签临时终端证书。真实中心/PG/资料均为新夹具，不恢复已清理的旧中心或60容器；保护中的原网关 UNKNOWN 不动。
